# 공유 캘린더 탭 설계

## 왜 만드나

부부가 지금 TimeTree 공유 캘린더를 쓰는데 광고가 거슬린다. 이미 둘 다 매일 여는 가계부 앱에 캘린더를 넣어, 광고 없이 한 달 일정을 같이 본다. 데이터는 구글 캘린더에 둬서 앱 밖(구글 캘린더, 아이폰 캘린더)에서도 볼 수 있고, 앱을 그만 써도 일정이 남는다.

가장 중요한 순간은 **캘린더 탭을 열어 이번 달 일정을 훑어보는 것**이다. 일정 추가는 그다음이다.

## 목표

- 탭 바에서 내역 탭 **왼쪽**에 '캘린더' 탭을 둔다. 안드로이드 앱(A)과 iOS 웹앱(B) 모두 같은 화면이다.
  - **앱을 켜면 캘린더 탭이 먼저 열린다**(사용자가 정한 것). 캘린더가 `/`가 되고 내역은 새 경로(예: `/list`)로 옮긴다.
  - 지금 `/`로 이동하는 기존 흐름(내역 저장 후 복귀, 수집함·월 합계·가져오기 화면에서 돌아가기, iOS 단축어 `?text=` 진입 등)은 하나씩 확인해서, 내역으로 가야 하는 곳은 새 내역 경로로 바꾼다.
- 이번 달 달력을 한 화면에 보여준다. 날짜 칸 안에 일정 제목이 대상별 배경색으로 보인다.
- 일정을 추가·수정·삭제할 수 있다. 입력 항목은 제목, 하루 종일/시간, 반복, 대상뿐이다.
- 기존 TimeTree 일정을 이 캘린더로 옮긴다(일회성 작업).
- 가계부 전체의 사람 표시 이름을 실명으로 바꾼다(아래 '이름' 참고).

## 하지 않는 것

- iOS 위젯, 푸시 알림, 일정 알림 설정. (B는 위젯을 쓰지 않는다.)
- 메모, 장소, 첨부, 댓글, 게스트 초대.
- 여러 캘린더 관리. 구글 캘린더는 **하나**만 쓴다.
- 주간·일간 보기. 월 보기 + 날짜별 바텀시트만 만든다.

## 실패로 보는 것 (돌아가도 안 되는 것)

- 실명이 공개 저장소(코드, 문서, 테스트, 빌드 산출물)에 들어가는 것.
- 캘린더 ID, 토큰, 엔드포인트가 저장소나 웹 빌드에 들어가는 것.
- 구글 캘린더에서 게스트 초대 메일이 나가는 것.
- 폴드 펼친 화면처럼 세로가 짧은 화면에서 달력이 스크롤해야 보이는 것.

## 정해진 것

### 데이터: 구글 캘린더 하나

- A의 구글 계정에 새 캘린더를 하나 만든다(사용자가 직접 구글 캘린더 웹에서 한다). 앱은 서버를 통해 A 계정으로 읽고 쓰므로 B 계정 공유는 **필요 없다**. B가 앱 밖(아이폰·구글 캘린더 앱)에서도 보고 싶을 때만 공유한다(선택).
- 지금의 시트 서버(Apps Script, A 계정으로 실행)가 `CalendarApp` / 고급 Calendar 서비스로 이 캘린더를 읽고 쓴다. 앱은 지금처럼 연결 코드(엔드포인트+토큰)만 안다. 앱에 구글 로그인을 붙이지 않는다.
- 캘린더 ID는 Apps Script의 스크립트 속성이나 gitignore된 `Secret.gs`에 둔다. 저장소에 넣지 않는다.

### 대상 (누구의 일정인가)

일정마다 대상 하나를 고른다.

| 대상 | 뜻 | 달력 표시 |
|---|---|---|
| 공동 | 둘이 함께 | 공동 배경색 + A·B 짤 나란히 (A 먼저) |
| A | A 개인 | A 배경색 + A 짤 |
| B | B 개인 | B 배경색 + B 짤 |
| 없음 | 그날의 이벤트 (예: 대형마트 휴무일) | 중립(회색 계열) 배경, 짤 없음 |

- 화면의 선택지 이름은 공동 / (A 표시 이름) / (B 표시 이름) / 없음 순서다. 표시 이름은 설정의 이름을 쓴다.
- 대상은 구글 일정의 **비공개 확장 속성**(`extendedProperties.private`)에 저장한다. 구글 '참석자(게스트)'는 쓰지 않는다(초대 메일 방지).
- 앱이 저장할 때 대상별로 **구글 일정 색(colorId)**도 같이 정해서, 구글·아이폰 캘린더에서도 색으로 구분되게 한다.
- 앱 밖에서 만든 일정(대상 속성이 없음)은 '없음'으로 보여준다. 수정 화면에서 대상을 고르면 그때 저장된다.

### 이름

- 가계부 전체에서 사람 이름을 실명으로 보여준다. 쿠리만쥬/우사기는 짤·이모지로만 남는다.
- 이미 있는 **설정 > 닉네임** 기능에 실명을 넣어서 해결한다. 실명은 시트 설정에만 저장되고 코드에는 들어가지 않는다.
- 내부 키(`Person = '쿠리만쥬' | '우사기'`, 시트의 '사람' 열)는 바꾸지 않는다.
- 화면에 '쿠리만쥬', '우사기' 글자가 직접 보이는 곳이 있으면 `displayName`을 거치도록 고친다.

### 캘린더 화면

- **달력 칸**: 그 달이 걸친 주 수만큼(5주 또는 6주) 보인다. 탭 바와 상단 머리 사이의 남은 높이를 주 수로 나눠 채우고, 세로 스크롤 없이 한 화면에 들어가야 한다. 사용자가 폰(폴드)에서 써 보고 줄여 달라고 할 수 있다.
- **월 이동**: 상단 가운데 년월 표기는 **내역 탭과 같은 모양**이다(`PeriodSwitcher`: ◀ 2026년 10월 ▾ ▶, 가운데를 누르면 고르는 시트). 사용자가 정한 것.
  - 다만 캘린더는 **다음 달 이후로도 넘어갈 수 있어야** 하고(내역은 이번 달까지만), **월 단위만** 쓴다(연 단위 없음). 기존 컴포넌트에 옵션을 더하거나 같은 모양의 캘린더용 변형을 만든다.
  - 캘린더가 보는 달은 내역 탭의 기간과 따로 기억한다(내 판단). 탭을 오갈 때 서로 끌려가지 않게.
  - 과거 쪽 하한(내역의 `2025-01`)도 캘린더에는 두지 않는다(내 판단). TimeTree에서 옮긴 오래된 일정도 볼 수 있게.
  - 좌우 스와이프로도 달을 넘긴다(내 판단).
- **날짜 숫자 색**: 일요일 빨강, 토요일 파랑. 숫자에만 색을 준다. 지난달·다음달 날짜는 흐리게. 오늘은 숫자에 동그라미 강조(내 판단).
- **일정 막대**: 날짜 칸 안에 한 줄씩 쌓는다. 대상 배경색 + 왼쪽에 작은 짤 + 제목. 칸 너비를 넘는 제목은 잘린다(말줄임). 칸 높이를 넘는 일정은 '+N'으로 줄인다(내 판단).
  - '없음' 일정은 다른 일정보다 위에 둔다(내 판단).
  - 여러 날에 걸친 일정은 시작일부터 끝날까지 각 날짜 칸에 반복해서 보인다(내 판단, 이어진 막대로 그리는 건 나중 일).
- **날짜를 누르면** 바텀시트에 그날 일정 전체를 시간순으로 보여준다(하루 종일 먼저). 일정마다 대상 짤, 제목, 시간, 반복 여부. 일정을 누르면 수정 화면. 시트 안의 ＋ 버튼은 그 날짜로 새 일정을 연다.
- **오른쪽 아래 둥둥이 ＋ 버튼**: 오늘(또는 지금 보는 달의 1일, 이번 달이 아니면) 날짜로 새 일정을 연다(내 판단).

### 일정 입력

- 제목(필수), 하루 종일 스위치, 시작/끝 날짜·시간, 반복(없음 / 매일 / 매주 / 매월 / 매년), 대상.
- 반복은 구글 캘린더 반복 규칙(RRULE)으로 저장해 다른 캘린더 앱에서도 똑같이 반복된다.
- 반복 일정의 한 회차를 고치거나 지울 때 **'이 일정만 / 이후 모두 / 전체'**를 고른다(사용자가 정한 것). 구글 캘린더의 방식과 같다.
  - 이 일정만: 그 회차만 예외로 바꾸거나 지운다.
  - 이후 모두: 그 회차부터 새 반복으로 나누고, 이전 회차는 그대로 둔다.
  - 전체: 반복 전체를 바꾼다. 날짜를 옮기면 회차 간 간격만큼 시리즈 시작일도 옮긴다.
  - 서버 쓰기 요청은 회차 id와 원래 회차 시작 시각을 받아야 한다.

### 데이터 흐름

- 서버에 `calendar` 읽기 요청(기간 지정)과 쓰기 요청(추가/수정/삭제)을 추가한다. 반복 일정은 서버가 기간 안의 날짜로 펼쳐서 돌려준다.
- 앱은 보고 있는 달(앞뒤 주 포함)을 불러와 Dexie에 캐시하고, 캐시를 먼저 보여준 뒤 새로 받아 바꾼다. 화면에 들어올 때와 앱이 다시 켜질 때 새로 받는다.
- 쓰기는 온라인일 때만 한다. 실패하면 오류 문구를 보여주고 입력 내용은 지우지 않는다. (가계부 내역처럼 outbox로 미뤄 보내지 않는다 — 내 판단, 캘린더는 구글이 원본이라 충돌 처리를 피한다.)
- 서버 쓰기 기능을 추가하는 Apps Script 재배포는 사용자에게 먼저 묻는다.

### TimeTree 옮기기

1. 사용자가 TimeTree-Exporter(비공식)로 공유 캘린더를 `.ics`로 내보낸다. 로그인이 필요해서 사용자가 직접 한다.
   - **지난 일정까지 전부** 옮긴다(사용자가 정한 것). 건수는 몇천 건보다 적을 것으로 본다. 정확한 수는 내보낸 파일의 `BEGIN:VEVENT` 개수로 확인한다.
2. 그 파일을 읽어 대상을 정한다. 참여자 정보가 있으면 참여자로(둘 다 → 공동, 한 명 → 그 사람), 없으면 색 라벨로(색-대상 대응은 사용자가 알려준다), 둘 다 없으면 '없음'.
3. 서버의 쓰기 요청으로 구글 캘린더에 넣는다(대상 속성과 색이 같이 들어가야 해서 구글 웹의 '가져오기'는 쓰지 않는다). 넣기 전에 몇 건이 어느 대상으로 가는지 보여주고 확인받는다.
4. 반복 일정은 반복 규칙 그대로 옮긴다.
5. 다시 실행해도 중복되지 않게, `.ics`의 UID를 확장 속성에 저장하고 이미 넣은 UID는 건너뛴다. 건수가 많으면 Apps Script 실행 시간(6분) 안에 끝나도록 나눠 보낸다(내 판단).

이 작업은 앱 기능이 아니라 일회성 스크립트로 한다. `.ics` 파일과 변환 결과는 저장소에 넣지 않는다.

## 빌더에게 맡기는 것

- 대상별 배경색 값(지금 디자인 토큰의 tone 색에서 고른다, 다크 모드 포함).
- 바텀시트·입력 화면의 세부 배치. 기존 ConfirmSheet, EditPage 스타일을 따른다.
- 서버 요청의 이름과 응답 모양, Dexie 테이블 구조.
- 짤 크기(막대 높이에 맞춘다).

## 남은 질문

- TimeTree 색 라벨이 각각 어떤 대상을 뜻하는지 (옮기기 단계에서, 내보낸 파일을 보고 확인).
