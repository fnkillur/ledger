# 주기 관리 (교체 D-day · 다녀온 지 D+) 설계

## 왜 만드나

수건(1년), 정수기 필터(6개월)처럼 주기적으로 바꿔야 하는 것을 자꾸 잊는다. 미용실·치과처럼 정해진 주기는 없지만 "다녀온 지 얼마나 됐지?"가 궁금한 것도 있다. 둘 다 한눈에 보고, 필요하면 폰 알림으로 받고 싶다.

캘린더의 반복 일정으로는 안 된다. 정수기 필터를 예정보다 2주 늦게 갈면 다음 교체일도 2주 밀려야 하는데, 반복 일정은 처음 정한 날에 고정된다. 그래서 "마지막으로 한 날 + 주기"로 다음 날짜를 계산하는 별도 기능으로 만든다.

## 목표

- 항목마다 "마지막으로 한 날"을 기억하고, 다음까지 남은 날(D-day) 또는 지난 날(D+)을 보여 준다.
- "했어요"를 누르면 오늘(또는 고른 날)로 마지막 날을 바꿔 주기를 다시 시작한다.
- 미용실·치과 같은 항목은 가계부 결제 기록에서 마지막 날을 자동으로 가져온다.
- 항목마다 폰 알림을 켜고, 언제 받을지 고른다. 등록할 때와 수정할 때 모두 고칠 수 있다.
- 두 사람이 모든 항목을 함께 본다. 항목마다 대상(공동/쿠리만쥬/우사기)이 있다.

## 하지 않는 것

- 유통기한 관리. 성격이 달라서(항목이 많고, 며칠 만에 사라지고, 입력 수고가 핵심) 나중에 별도 프로젝트로 한다.
- 구글 캘린더에 일정으로 넣기. 캘린더 화면에 표시만 하고, 구글 캘린더 데이터는 건드리지 않는다.
- 알림 시각 고르기. 하루 한 번 정해진 시각에만 보낸다.

## 실패로 볼 것

- 결제 기록 자동 연결이 엉뚱한 결제를 잡아 날짜가 틀렸는데 고칠 방법이 없는 것.
- 알림이 대상이 아닌 사람에게 가거나, 같은 알림이 하루에 여러 번 오는 것.
- 하단 탭이 늘어 화면이 비좁아지는 것.

## 정한 것

### 어디에 두나

- 캘린더 탭 안에 "일정 | 주기" 전환을 두고, '주기' 화면에 목록을 보여 준다. 하단 탭은 늘리지 않는다.
- 캘린더 화면에는 다음 교체일(주기가 있는 항목만)에 작은 표시를 해서 그날 할 일로 같이 보이게 한다. 날짜를 눌러 여는 그날 목록에도 함께 보여 준다.

### 항목

| 필드 | 설명 |
| --- | --- |
| 이름 | 예: 수건 교체, 정수기 필터, 치과 |
| 아이콘 | 이모지 하나 (선택) |
| 대상 | 공동 / 쿠리만쥬 / 우사기. 캘린더 일정의 대상 표시와 같은 색·아바타를 쓴다 |
| 주기 | 없음 또는 N일/N주/N개월/N년. 없으면 D+만 보여 준다 |
| 마지막으로 한 날 | 직접 기록한 날 ("했어요"). 등록 폼에서 넣는 날짜도 `주기기록` 한 줄로 저장한다 |
| 결제 연결 | 없음 또는 조건: 카테고리(하나) + 가맹점에 들어가는 말(하나) + 결제한 사람. 카테고리나 가맹점 말 중 하나는 꼭 있어야 한다(사람만으로는 연결하지 않는다). 공동/개인 구분은 보지 않는다 |
| 알림 | 끔 또는 켬 + 보낼 때(여러 개): 당일, 1일 전, 3일 전, 7일 전. 주기가 없는 항목은 "주기 대신 N일 지나면 알림" 하나만 고를 수 있다 |
| 메모 | 선택 |

- **실제 마지막 날** = 직접 기록한 날과 결제 연결로 찾은 마지막 결제일 중 더 최근 날짜. 결제 기록이 엉뚱하면 "했어요"로 더 최근 날짜를 넣어 덮을 수 있다.
  - 결제가 실제보다 더 최근에 잡혀서 틀린 경우는 연결 조건을 고쳐서 해결한다(예: 결제한 사람 지정).
- 결제 연결은 지출만 본다. 통계 제외 기록은 포함하고(대신 결제한 경우도 다녀온 날로 본다), 삭제된 기록과 한 달 치를 묶은 기록(`isAggregate`: 월합계·이관)은 뺀다. *(빌더 검토 후 정함)*
- **다음 날짜** = 실제 마지막 날 + 주기. 월·년 단위는 달력 기준으로 더한다(1월 31일 + 1개월 → 2월 말일).

### 목록 화면

- 주기 있는 항목: "D-23", 지났으면 "D+5"를 강조색으로 보여 준다. 마지막 날부터 다음 날까지 얼마나 왔는지 진행 막대를 보여 준다.
- 주기 없는 항목: "D+47 · 9월 18일" 처럼 지난 날과 마지막 날을 보여 준다. 결제로 잡힌 날이면 어떤 결제인지(가맹점) 작게 보여 준다.
- 정렬: 기한이 지났거나 가까운 순 → 주기 없는 항목은 오래된 순으로 아래에.
- 대상으로 거르기: 전체 / 공동 / 쿠리만쥬 / 우사기.
- 항목의 "했어요" 버튼은 누르면 오늘로 기록하고, 잠깐 되돌리기를 보여 준다. 다른 날로 기록하려면 항목을 열어 날짜를 고른다.
- 항목을 누르면 수정 폼(등록 폼과 같은 폼)으로 간다. 지난 기록(언제 했는지 목록)을 아래에 보여 주고, 각 기록의 날짜를 고치거나 지울 수 있다(소프트 삭제, 동기화). 잘못 누른 "했어요"를 나중에도 바로잡기 위해서다. *(빌더 검토 후 정함)*
- 항목이 하나도 없으면 예시(수건 1년, 정수기 필터 6개월, 칫솔 3개월, 치과)를 눌러 바로 추가할 수 있게 한다.

### 알림

- 이미 있는 FCM 경로(Push.gs, 안드로이드 앱 + 아이폰 홈 화면 웹앱)를 그대로 쓴다.
- Apps Script 시간 트리거가 매일 오전 9시(Asia/Seoul)에 한 번 돌며, 오늘 보낼 알림을 찾아 보낸다.
- 받는 사람: 대상이 공동이면 두 사람 모두, 개인이면 그 사람에게만. (기존 일정 알림은 "상대방에게" 보내지만, 이건 대상에게 보낸다.)
- 문구 예: "정수기 필터 교체 3일 남았어요", "오늘 정수기 필터 바꾸는 날이에요", "치과 다녀온 지 180일 됐어요".
- 알림은 고른 시점마다 한 번씩만 보낸다. 기한이 지난 뒤에는 "했어요"를 누르지 않았어도 다시 보내지 않는다. 주기 없는 항목의 "N일 지나면 알림"도 그날 한 번만 보낸다. *(사용자 결정)*
- 트리거가 같은 날 두 번 돌아도 같은 항목·같은 시점 알림이 두 번 가지 않게 보낸 기록을 남긴다. 마지막 날이 바뀌면(했어요) 새 주기의 알림은 다시 보낼 수 있다.
- 알림을 누르면 앱의 주기 화면, 그 항목으로 연다.
- 트리거는 편집기에서 한 번 설치하는 함수(`installCycleTrigger`)로 만든다. 서버 배포 규칙(사용자가 "서버 배포 해줘"라고 할 때만)을 따른다.

### 저장과 동기화

- 구글 시트에 새 탭 두 개를 둔다: `주기항목`(항목), `주기기록`(직접 기록한 날 이력: 항목 id, 날짜, 사람, 기록 시각).
- 앱은 지금의 거래내역처럼 로컬 DB(Dexie)에 두고 outbox로 올리고, pull에서 `동기화시각 > since`로 받는다. 삭제는 소프트 삭제.
- 결제 연결로 찾는 마지막 결제일은 저장하지 않고, 앱에서는 로컬 거래내역으로, 서버(알림)에서는 시트 거래내역으로 그때그때 계산한다. 계산 규칙은 앱과 서버가 같아야 하므로 한 곳에 명세하고 양쪽에 같은 테스트 사례를 둔다.

## 빌더에게 맡기는 것

- 화면 세부 배치, 진행 막대·D-day 표시의 시각 디자인(기존 카드·칩 스타일을 따른다).
- 주기 입력 UI 형태(숫자 + 단위 고르기 등).
- 로컬 DB 스키마 버전 올리기와 시트 열 이름.
- 예시 항목의 정확한 목록.

## 제약

- 실명은 코드·테스트·문서·커밋에 넣지 않는다(쿠리만쥬/우사기만).
- 비밀값(토큰, 엔드포인트, 스크립트 ID, 키)은 저장소·웹 빌드에 넣지 않는다.
- 실제 시트·캘린더에 테스트 데이터를 쓰지 않는다.
- 커밋은 사용자 검토 후, 웹 배포·서버 배포는 사용자가 요청할 때만.
